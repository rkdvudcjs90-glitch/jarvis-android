# Claude Code + Codex 공동 개발

목표는 같은 코드와 요구사항을 공유하며 작은 변경을 서로 검토하는 것이다.
현재 상태는 '연결 준비'다. Claude Code의 로그인·저장소 접근 승인과 실제 세션 실행은 완료되지 않았다.

## 담당
- Claude Code: 요구사항/오류 분석, 합의된 범위의 설계·구현.
- Codex: 독립 코드 검토, 실패 상황 재현, 회귀 검사와 변경 통합 지원.
- 창업자: 제품 방향과 충돌하는 요구사항 결정, 외부 계정 로그인, 실제 사용자 기기에서만 가능한 정보 제공.
- 필요하면 작업별로 구현/검토 담당을 교대하되 같은 변경을 작성한 담당이 독립 검토자로 서명하지 않는다.

## 작업 한 건의 순서
1. 현재 커밋·브랜치와 작업 문서를 확인한다. 다른 작업자가 수정 중인 파일을 파악한다.
2. 증상·재현 조건·수정 가능한 경로·완료 기준을 짧게 기록한다.
3. 담당 브랜치에서 최소 변경을 작성한다. 기본 형식은 `claude/task-001-설명`, `codex/task-001-review`다.
4. 실제 실행 명령과 결과를 기록한다. 검사하지 못한 항목은 실패/미실행 사유를 기록한다.
5. 다른 담당이 해당 커밋의 변경을 확인하고 재현/회귀 결과를 검토한다. 실패하면 그 항목만 수정한다.
6. PR은 변경·근거·검증 한계 중심으로 작성한다. 기존 서명/앱 식별자/저장 데이터 호환성을 확인한 뒤 통합한다.
7. APK 공개는 테스트한 커밋·앱 식별자·버전·서명·SHA-256을 묶어 보고한다. 자동 무한 리뷰·자동 결제/배포를 켜지 않는다.

## 공유 수단
- 코드는 GitHub 브랜치/커밋, 작업 상태와 인수인계는 docs/team/, 검토 결과는 PR을 사용한다.
- 두 서비스의 채팅 내용이 자동으로 공유되는 것은 아니다. 필요한 결정과 증거만 문서로 남긴다.
- 같은 파일을 동시에 수정하지 않는다. 공유 작업 디렉터리를 쓸 때는 별도 checkout/worktree를 사용한다.
- 애플리케이션의 API 키와 Claude Code/Codex 개발 도구의 로그인은 별개다. 이 협업 준비 작업은 앱에 Claude API 키를 추가하지 않는다.

## 비용과 실행 제한
- 지금은 공동개발 준비 브랜치만 만든다. main 변경·APK 새 배포·유료 API 시험·Claude 자동 호출은 하지 않는다.
- 기존 CI는 main push 또는 PR에서 실행된다. 문서 준비만으로 긴 빌드/에뮬레이터 작업을 만들지 않기 위해 이 준비 단계에서는 PR을 자동 생성하지 않는다.
- Claude의 첫 작업은 읽기 중심 감사다. 빌드가 필요한 근거가 없으면 모델 다운로드/전체 APK 빌드를 하지 않는다.
- 이후 실제 코드 PR에서는 기존 CI를 유지하고 변경에 맞는 검사를 실행한다.

## 결과 기록 형식
- 담당 도구 / 기준 커밋 / 작업 브랜치 / 수정 파일.
- 재현한 증상, 원인과 근거, 실제 변경.
- 실행한 명령과 결과, 검사 종류, 재검사 사유.
- 독립 검토 담당과 검토 커밋. 미실행이면 그 상태 그대로 기록.
- 남은 문제와 다음 작업. 전체 완성·오류 0개 같은 확인하지 않은 주장을 하지 않는다.
